# Database-Agnostic Architecture 🎯

This document explains how we've transformed the Restaurant Analytics Template into a **super database-agnostic** system using dbt as the core abstraction layer.

## 🏗️ Architecture Overview

```
┌─────────────────┐    ┌─────────────────┐    ┌─────────────────┐
│   Data Sources  │    │   Python Layer  │    │   dbt Layer     │
│                 │    │                 │    │                 │
│ • Yelp API      │───▶│ • API Ingestion │───▶│ • Transformations│
│ • Google Places │    │ • Data Loading  │    │ • Business Logic │
│ • Future APIs   │    │ • Orchestration │    │ • Data Quality   │
└─────────────────┘    └─────────────────┘    └─────────────────┘
                                                        │
                                                        ▼
┌─────────────────┐    ┌─────────────────┐    ┌─────────────────┐

│                 │    │                 │    │                 │
```

## 🔄 What Changed: Before vs After

### Before (Tightly Coupled)
```python
# Python did everything - not portable
df['price_category'] = df['price_level'].apply(lambda x: 'Budget' if x <= 1 else 'Expensive')
df['rating_category'] = df['rating'].apply(lambda x: 'High' if x >= 4.0 else 'Low')
df['business_tier'] = calculate_business_tier(df['rating'], df['review_count'])
```

### After (Database-Agnostic)
```sql
-- dbt macros work on any database
SELECT 
  {{ price_category('price_level') }} as price_category,
  {{ rating_category('rating') }} as rating_category,
  {{ business_tier('rating', 'review_count') }} as business_tier
FROM {{ source('raw_data', 'raw_restaurant_data') }}
```

## 🎯 Key Benefits

### 1. **Database Portability**
- **Change one configuration file** to switch databases
- **Same SQL logic** works on BigQuery, Snowflake, PostgreSQL, etc.
- **No Python code changes** required for database migration

### 2. **Separation of Concerns**
- **Python**: API ingestion, orchestration, raw data loading
- **dbt**: All business logic, transformations, data quality
- **Dashboard**: Visualization of clean, transformed data

### 3. **Maintainability** 
- **Single source of truth** for business logic in dbt
- **Version-controlled** SQL transformations
- **Testable** and **documentable** data models

### 4. **Performance**
- **Database-native** SQL execution (faster than Python)
- **Incremental models** for large datasets
- **Optimized** queries generated by dbt

## 🛠️ Database-Agnostic Components

### 1. **dbt Macros** (`dbt_project/macros/`)

#### Restaurant Transformations
```sql
-- Works on ANY database that dbt supports
{% macro price_category(price_level_col) %}
  CASE 
    WHEN {{ price_level_col }} = 1 THEN 'Budget'
    WHEN {{ price_level_col }} = 2 THEN 'Mid-range'  
    WHEN {{ price_level_col }} = 3 THEN 'Expensive'
    ELSE 'Unknown'
  END
{% endmacro %}
```

#### Database-Specific Logic
```sql
-- Automatically adapts to database syntax
{% macro safe_numeric_cast(column_name, default_value=0) %}
  {% if target.type == 'bigquery' %}
    COALESCE(SAFE_CAST({{ column_name }} AS FLOAT64), {{ default_value }})
  {% elif target.type == 'snowflake' %}
    COALESCE(TRY_CAST({{ column_name }} AS FLOAT), {{ default_value }})
  {% elif target.type == 'postgres' %}
    COALESCE({{ column_name }}::NUMERIC, {{ default_value }})
  {% endif %}
{% endmacro %}
```

### 4. **Simplified Python** (`ingestion/spark_processor.py`)

```python
def _apply_pandas_transformations(self, df: pd.DataFrame) -> pd.DataFrame:
    """Apply minimal transformations - most logic moved to dbt."""
    
    # Only basic data type conversions for database compatibility
    numeric_columns = ['rating', 'price_level', 'user_ratings_total', 'latitude', 'longitude']
    for col in numeric_columns:
        if col in df.columns:
            df[col] = pd.to_numeric(df[col], errors='coerce')
    
    # Add audit fields
    df['ingestion_timestamp'] = pd.Timestamp.now()
    
    # Everything else handled by dbt! ✨
    return df
```

## 🚀 Migration Instructions

### To Switch Databases:

1. **Update dbt profile** (`dbt_project/config/dbt_profiles.yml`):
```yaml
# From BigQuery
type: bigquery

# To Snowflake  
type: snowflake
account: your_account
user: your_user
# ... other Snowflake settings
```

2. **Update Python config** (`ingestion/utils.py`):
```python
# Replace get_bigquery_config with get_snowflake_config
def get_snowflake_config():
    return {
        'account': os.getenv('SNOWFLAKE_ACCOUNT'),
        'user': os.getenv('SNOWFLAKE_USER'),
        # ... other settings
    }
```

3. **Update dependencies** (`requirements.txt`):
```bash
# Replace
google-cloud-bigquery
dbt-bigquery

# With  
snowflake-connector-python
dbt-snowflake
```

4. **Test the migration**:
```bash
# Test dbt connection
cd dbt_project && dbt debug

# Run transformations
dbt run

# Test pipeline
python3 orchestration/flow.py
```

**That's it!** All business logic, transformations, and analytics work exactly the same on the new database.

## 💡 Best Practices

### 1. **Keep Python Minimal**
- Only handle API ingestion and raw data loading
- Move ALL business logic to dbt
- Use Python for orchestration, not transformation

### 2. **Use dbt Macros Everywhere**
- Create reusable, database-agnostic functions
- Handle database-specific syntax in macros
- Test macros across different databases

### 3. **Design for Quality**
- Implement data quality checks in dbt
- Use dbt tests for validation
- Track data lineage and freshness

### 4. **Plan for Scale**
- Use incremental models for large datasets
- Implement proper indexing/clustering
- Monitor performance across databases
